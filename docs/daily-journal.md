# اليومية الإلكترونية — Daily Journal (PDF / Excel / on-screen)

هذا المستند يوصّف إعادة بناء «يومية المنيا» الورقية إلكترونيًا كما هي مُنفَّذة الآن
في الكود، وهو المرجع الوحيد لترتيب الأقسام والأعمدة والمعادلات.

## 1. الحقول المالية المعتمدة (لكل منفذ ولكل وردية)

| العمود | طريقة التسجيل | ملاحظة |
| --- | --- | --- |
| الرسوم اليدوية | إدخال المستخدم | مستقل |
| الرسوم الآلية | إدخال المستخدم | مستقل |
| إجمالي الرسوم | إدخال المستخدم | **مستقل تمامًا** عن اليدوي والآلي |
| إجمالي الموازين | **محسوب** | `الإجمالي العام − إجمالي الرسوم` |
| NFC | إدخال اختياري | محفوظ كصفر عند تركه فارغًا |
| VISA | إدخال اختياري | محفوظ كصفر عند تركه فارغًا |
| الإجمالي العام | إدخال المستخدم | يحتوي NFC وVISA بالفعل |

قواعد إلزامية منفَّذة في `lib/models/collection_amounts.dart` و
`lib/models/daily_journal.dart`:

1. `إجمالي الموازين = الإجمالي العام − إجمالي الرسوم`
   ولا يتم جمع الرسوم اليدوية مع الآلية لحساب إجمالي الرسوم أبدًا.
2. NFC وVISA لا تُضاف مرة أخرى إلى الإجمالي العام.
3. إجمالي الموازين حقل محسوب غير قابل للتعديل اليدوي في الواجهة.
4. جميع الإجماليات التجميعية (الوردية/المنفذ/اليوم) تُحسب بنفس المنطق في
   PDF وExcel والواجهة من نفس الكائن `DailyJournal`.

مثال الاختبار المعتمد (منفّذ فعليًا في `test/daily_journal_test.dart`):

```
اليدوي 2000 | الآلي 3000 | إجمالي الرسوم 5500 | الإجمالي العام 10000
NFC 1000 | VISA 500  ->  إجمالي الموازين 4500
```

## 2. ترتيب أقسام اليومية

1. بيانات منافذ الوردية الأولى.
2. إجمالي الوردية الأولى (صف أصفر).
3. بيانات منافذ الوردية الثانية.
4. إجمالي الوردية الثانية (صف أصفر).
5. الوردية الثالثة وإجماليها — تظهر فقط عند تفعيلها لمنفذ واحد على الأقل.
6. **إجمالي اليوم لكل منفذ** — صف مستقل لكل منفذ يجمع كل وردياته لكل عمود.
7. الإجمالي العام لليوم — مجموع صفوف القسم (6) بدون احتساب مزدوج.

ترتيب المنافذ داخل كل قسم هو ترتيب الطباعة المحفوظ في `outlets.sort_order`
(قابل للتغيير من شاشة المنافذ دون أي تأثير على البيانات التاريخية).

## 3. العناصر المستبعدة

استُبعدت عن قصد لأنها ليست جزءًا من اليومية الإلكترونية:

- «مسلم الإداري» و«مسلم الرقابة».
- «المتبقي» وحسابات تسليم المبالغ.

ولم تُستحدث حقول مالية مستقلة لأعمدة «الدهسا» أو «الرقابة»؛ فهي أسماء منافذ
تُدار من الإعدادات وتظهر كصفوف، وليست أعمدة مالية.

## 4. الألوان والتنسيق (مطابقة للورقة)

| العنصر | اللون |
| --- | --- |
| رأس الجدول | أبيض بنص أسود |
| مجموع أول خمسة منافذ في كل وردية | خلية خضراء مدمجة في يسار عمود الإجمالي العام، تعرض مجموع الصفوف المتاحة حتى خمسة |
| شريط قسم الوردية | `#F2F0EE` |

| حدود الخلايا | `#1F2937` |

## 5. PDF

`lib/services/daily_journal_pdf_service.dart`

- A4 بالعرض (landscape) باتجاه RTL، خط Amiri المدمج (عربي متصل).
- عرض ثابت لكل عمود محسوب من عرض الصفحة ⇒ لا يُقص أي عمود ولا تتداخل البيانات.
- يظهر عنوان اليومية والتاريخ ورأس الجدول في كل صفحة.
- الجدول يمتد على أي عدد من الصفحات حسب عدد المنافذ والورديات.
- المعاينة والحفظ والطباعة تتم باستخدام نفس ملف PDF المعروض داخل البرنامج.

## 6. Excel

`lib/services/excel_export_service.dart` + `lib/services/xlsx_print_setup.dart`

- خلايا رقمية حقيقية (وليس نصوصًا) للرسوم والمدفوعات والإجماليات.
- معادلات Excel فعلية:
  - إجمالي الموازين: `=H{row}-D{row}` (الإجمالي العام − إجمالي الرسوم).
  - إجمالي الوردية: `=SUM(...)` على صفوف الوردية نفسها.
  - إجمالي اليوم لكل منفذ: `=SUM(صفوف المنفذ في كل الورديات)`.
  - الإجمالي العام لليوم: `=SUM(صفوف إجمالي اليوم لكل منفذ)` دون احتساب مزدوج.
  - `إجمالي الرسوم` يبقى قيمة مُدخلة (ليس معادلة جمع) حفاظًا على استقلاليته.
- RTL لكل ورقة، ألوان وحدود وخلايا مدمجة لعناوين الأقسام.
- منطقة طباعة مُعرَّفة (`_xlnm.Print_Area`)، اتجاه عرضي، `fitToWidth=1`،
  تجميد رأس الجدول، و`fullCalcOnLoad=1` لإعادة حساب الإجماليات عند الفتح
  وعند تعديل أي خلية.
- إذا تعذّر تعديل ملف OOXML لأي سبب يُعاد الملف الأصلي كما هو (لا يُنتج ملف تالف).

## 7. تطابق PDF وExcel

كلاهما يُبنى من نفس الكائن `DailyJournal` (نفس الأرقام ونفس الترتيب ونفس الأقسام)،
و`test/journal_exports_test.dart` يتحقق من:

- تطابق كل خلية رقمية في Excel مع قيم النموذج.
- صحة معادلات `SUM` بحساب مجموع الخلايا المُشار إليها ومقارنته بالإجمالي المطلوب.
- وجود معادلة الفرق في عمود إجمالي الموازين.
- وجود منطقة الطباعة والاتجاه العرضي والتجميد في OOXML.
- توليد PDF بأكثر من صفحة عند زيادة عدد المنافذ دون فقد رأس الجدول.
