# RAGAA (رجاء) — نظام إدارة تحصيل المنافذ

تطبيق محاسبي عربي (RTL) مبني بـ **Flutter** لإدارة تحصيل عدة منافذ وورديات، مع
قاعدة بيانات **SQLite** محلية، وتقارير يومية/أسبوعية/شهرية/مخصصة، وتصدير
**PDF** و**Excel**، ونسخ احتياطي واستعادة آمنين.

يعمل البرنامج على **Windows** (مثبّت `RAGAA-Setup.exe`) و**Android** (APK مستقل
بقاعدة بيانات محلية، دون خادم أو مزامنة).

---

## 1. الحقول والمعادلات المالية المعتمدة

لكل منفذ ولكل وردية:

| البيان | طريقة التسجيل |
| --- | --- |
| الرسوم اليدوية | إدخال المستخدم |
| الرسوم الآلية | إدخال المستخدم |
| إجمالي الرسوم | إدخال المستخدم — **مستقل** عن اليدوي والآلي |
| إجمالي الموازين | **محسوب تلقائيًا** |
| NFC | إدخال اختياري (يُحفظ صفرًا إذا تُرك فارغًا) |
| VISA | إدخال اختياري (يُحفظ صفرًا إذا تُرك فارغًا) |
| الإجمالي العام | إدخال المستخدم |

**المعادلة الوحيدة المعتمدة:**

```
إجمالي الموازين = الإجمالي العام − إجمالي الرسوم
```

- إجمالي الرسوم **لا** يُحسب بجمع الرسوم اليدوية والآلية.
- NFC وVISA جزء من الإجمالي العام ولا تُضاف إليه مرة أخرى.
- إجمالي الموازين غير قابل للتعديل اليدوي.
- كل الإجماليات التجميعية (وردية/منفذ/يوم) تُحسب بنفس المنطق الموحّد في كل
  أجزاء التطبيق: الواجهة، PDF، Excel.
- كل المبالغ تُخزَّن كأعداد صحيحة بالقروش (`INTEGER`) لمنع أخطاء التقريب.

مثال الاختبار الآلي المعتمد: يدوي 2000، آلي 3000، إجمالي الرسوم 5500،
الإجمالي العام 10000، NFC 1000، VISA 500 ⇒ **إجمالي الموازين 4500**.

## 2. اليومية الإلكترونية (PDF / Excel / شاشة)

تنفيذ إلكتروني ديناميكي لليومية الورقية (وليس صورة خلفية). التفاصيل الكاملة في
[`docs/daily-journal.md`](docs/daily-journal.md).

**ترتيب الأقسام:** بيانات الوردية الأولى ← إجماليها (أصفر) ← الوردية الثانية ←
إجماليها ← الوردية الثالثة (عند تفعيلها) ← **إجمالي اليوم لكل منفذ** (صف مستقل
لكل منفذ) ← الإجمالي العام لليوم (بدون احتساب مزدوج).

**الأعمدة (من اليمين):** البيان | الرسوم اليدوية | الرسوم الآلية | إجمالي الرسوم |
إجمالي الموازين | NFC | VISA | الإجمالي العام.

الخلية الخضراء تجمع أول خمسة منافذ داخل الوردية حسب ترتيب الطباعة.

**العناصر المستبعدة** تشمل «مسلم الإداري»، «مسلم الرقابة»،
«المتبقي»، وحسابات تسليم المبالغ. ولم تُستحدث حقول مالية مستقلة لأعمدة «الدهسا»
أو «الرقابة» لأنها **أسماء منافذ** تُدار من الإعدادات.

| | PDF | Excel |
| --- | --- | --- |
| الاتجاه | RTL، خط Amiri عربي متصل | `rightToLeft=1` |
| الحجم | A4 بالعرض | A4 عرضي، `fitToWidth=1` |
| الأعمدة | عرض ثابت لكل عمود (لا قص ولا تداخل) | أعمدة رقمية حقيقية |
| المعادلات | إجمالي الموازين يُحسب بنفس المعادلة | `=H-D` للفرق، `=SUM(...)` للإجماليات |
| تعدد الصفحات | عنوان اليومية والأعمدة تتكرر في كل صفحة | منطقة طباعة + تجميد الرأس |
| المعاينة والطباعة | معاينة داخلية بنفس ملف PDF + حفظ/طباعة | — |
| الألوان | أخضر مدمج لأول خمسة منافذ، أصفر لخلية الإجمالي العام بصف إجمالي الوردية، بنفسجي لباقي الإجماليات، بني لعمود الموازين | نفس الألوان |
| القيم | نفس قيم Excel بالضبط | نفس قيم PDF بالضبط |

**تقرير الفترة (PDF):** يُطبع الآن بعرض الصفحة (A4 landscape) لأن جدول التفاصيل
يحمل 13 عمودًا؛ لكل عمود عرض محسوب فلا يُقص رقم ولا يلتف على سطرين، ورأس الجدول
يتكرر في كل صفحة، مع صف إجماليات واحد في النهاية.

ملفات المعاينة الحقيقية في مجلد [`review`](review):
`ragaa_journal_2026-11-19.pdf`، `ragaa_journal_2026-11-19.xlsx`، وتقارير
`ragaa_report_*`.

## 3. إدارة المنافذ والورديات

- إضافة المنافذ يدويًا من الإعدادات (بلا أسماء أو أعداد مثبتة في الكود).
- «الدهسا» و«الرقابة» مجرد أسماء منافذ.
- ترتيب طباعة قابل للتغيير (أعلى/أسفل) ويُحفظ في `outlets.sort_order` ويُوثَّق في
  سجل المراجعة.
- ورديتان أو ثلاث لكل منفذ بشكل مستقل، مع مواعيد لكل وردية (بما يشمل الورديات
  الممتدة بعد منتصف الليل).
- تغيير عدد الورديات أو الاسم أو الترتيب **لا يفقد أي بيانات تاريخية** (لقطة
  الوردية محفوظة في كل سجل).

## 4. بقية الوظائف

- **لوحة المعلومات:** إجماليات، نسب مساهمة المنافذ، الورديات غير المسجلة اليوم.
- **التحصيل:** تسجيل/تعديل مع منع تكرار `(منفذ + تاريخ تشغيلي + وردية)` على مستوى
  التطبيق وقيد `UNIQUE` في قاعدة البيانات، وسجل مراجعة غير قابل للحذف.
- **التقارير:** يومية، أسبوعية (السبت–الجمعة)، شهرية، فترات مخصصة + فلاتر منافذ
  وورديات + بحث وتصفية.
- **التصدير:** PDF عربي RTL وExcel متعدد الأوراق (`ملخص التقرير`, `حسب المنفذ`,
  `حسب الوردية`, `حسب اليوم`, `تفاصيل التحصيل`, و`اليومية` في التقارير اليومية).
- **النسخ الاحتياطي والاستعادة:** `VACUUM INTO` + بصمة SHA-256 + فحص
  `PRAGMA integrity_check` + نسخة أمان تلقائية قبل أي استعادة.
- **الترحيل:** ترقية قواعد بيانات الإصدارات السابقة (v1 → v2 → v3) دون فقد بيانات،
  مع تحويل المبلغ القديم المفرد إلى «الإجمالي العام».

## 5. التشغيل والتثبيت

### Windows (للمستخدم النهائي)
1. نزّل `RAGAA-Setup.exe` من الـArtifacts (انظر §7).
2. شغّله واتبع الخطوات (اختصار Start + اختصار سطح المكتب الاختياري + إزالة تثبيت).
3. لا حاجة إلى Flutter أو Visual Studio؛ كل DLL المطلوبة (بما فيها `sqlite3.dll`)
   داخل مجلد التثبيت.

البيانات خارج مجلد التثبيت، لذلك:
`%APPDATA%\..\RAGAA\data\ragaa_accounting.db` و`Documents\RAGAA\{backups,exports}`
تبقى سليمة عند التحديث أو إزالة التثبيت العادية.

### Android
1. نزّل `RAGAA-release.apk` من الـArtifacts.
2. اسمح بالتثبيت من مصدر غير معروف إن طُلب ذلك (أو وقّع APK بمفتاحك الخاص).
3. التطبيق مستقل بقاعدة SQLite محلية؛ الملفات المصدَّرة تُحفظ في
   `Android/data/com.ragaa.ragaa/files/RAGAA/` ويمكن مشاركتها مباشرة عبر زر «مشاركة».

### التطوير محليًا
```bash
flutter pub get
flutter analyze
flutter test
flutter run -d windows     # أو -d linux / -d <android device>
```

### بناء المثبت والـAPK يدويًا
```powershell
flutter build windows --release
& "$env:ProgramFiles(x86)\Inno Setup 6\ISCC.exe" installer\ragaa.iss
# الناتج: artifacts\RAGAA-Setup.exe
```
```bash
flutter build apk --release
# الناتج: build/app/outputs/flutter-apk/app-release.apk
```

Workflow: `.github/workflows/ci.yml`

| Job | الناتج |
| --- | --- |
| Analyze & Test | `flutter analyze` + `flutter test` (سجلاتهما تُنشر في `review/ci/`) |

## 8. هيكل المشروع

- `lib/core/` — التنسيق والتواريخ التشغيلية والفترات والسمة.
- `lib/models/` — المنافذ، الورديات، التحصيل، سجل المراجعة، التقارير، **اليومية**.
- `lib/data/` — SQLite، الترحيلات، المستودع المحاسبي، النسخ الاحتياطي.
- `lib/services/` — تصدير PDF وExcel، **يومية PDF**، إعداد طباعة XLSX، مشاركة الملفات.
- `lib/state/` — متحكم الحالة.
- `lib/ui/` — الواجهة العربية المتجاوبة (سطح مكتب + موبايل).
- `installer/` — سكربت Inno Setup لبناء `RAGAA-Setup.exe`.
- `review/` — ملفات المعاينة الحقيقية وسجلات CI.
- `docs/` — مواصفات وتفاصيل التصميم.
